# Item Master Import

The Item Master uses one shared `item` table for all departments. Opening Item Master without a department filter lists all active items; the Sr. No. column is generated by the frontend from the displayed order and is not stored in the database.

## File format

CSV, XLS, and XLSX files must contain these columns in the first row:

`Item ID, Item Name, Description, Department, Packing, Gross Weight, Department ID`

`Item ID` is the immutable three-digit item code. `Department ID` is preferred; the Department name is accepted as a fallback. Packing must be a positive integer, and Gross Weight must be positive.

## Import behavior

- Existing Item IDs are skipped and returned as row-level duplicate issues.
- Duplicate Item IDs appearing more than once in the same upload are skipped.
- Invalid rows are skipped and returned with source row, Item ID, and a clear message.
- Valid non-duplicate rows are inserted in one database transaction.
- The UI shows the inserted count and opens a dismissible review dialog when issues exist.
- Existing Item IDs include a side-by-side comparison of the current database values and uploaded values. The user can load either version into the normal update form; changing the name alone never creates a second record with the same Item ID.
- Imported items are written to `audit_log` with the importing user and payload.
